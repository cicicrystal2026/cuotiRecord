# 版本文档规则

每个版本均在编码开始前建立独立文档目录 `docs/versions/vX.Y.Z/`。

| 文档 | 必须记录的内容 | 更新时间 |
|---|---|---|
| PRD.md | 本版目标、功能ID、流程、页面、字段、业务规则、异常、验收标准、明确不纳入的需求 | 开发前建立；功能变化时同步 |
| TECHNICAL.md | 架构、运行环境、模型接入、接口、数据模型、配置、持久化、迁移、异常、测试与已知限制 | 开发前给方案；实现后与代码一致 |
| ACCEPTANCE.md | 本地启动方式、逐功能验证步骤、预期结果、验证状态、真实AI与演示模式区别 | 开发前定义；验证时更新 |
| CHANGELOG.md | 新增、调整、移除、缺陷修复、数据兼容性、升级或回退说明 | 每次可验收交付更新 |

## 文档与代码一致性

1. 功能使用稳定ID，如F001。后续精简时保留ID并标记移除，不删除历史需求。
2. 页面原型或实现截图归档在版本目录的 `prototypes/`，PRD中逐页引用。开发前归档设计，交付时补充实际页面截图与差异。
3. 任何功能变更同时更新PRD、技术文档与验收项。旧版本发布后保持归档，修订必须记入变更记录。
4. 在实现尚未确定时明确标记“方案”或“待确定”；不能把设计目标写成已实现能力。
5. 数据库迁移必须编号并记录升级影响；修改模型、提示词或考点库也记录版本。模型分析结果保存当时版本，不能静默改写旧判断。
6. 发布前核对功能ID、验收结果、启动步骤与已知限制。没有运行的测试写“未验证”，失败的测试写明问题。

## 版本计划

- v0.1.0：本地单个孩子、单学科使用，完成全部P0闭环。
- v0.2.x：依据真实使用反馈选择P1功能，可删减当前流程，不默认开发所有P1。
- 后续版本：按使用价值决定P2，不预设云端、账号或付费体系。

本地验收采用真实文件与真实阿里云模型调用；没有API Key时可演示页面，但必须明确显示演示模式，不能把演示分析当作真实结果。
